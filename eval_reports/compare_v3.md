## Notes and ship recommendation

- v3 is the direct 32M run `v3_32_a03` (anchor weight 0.3, regret 0, v3 data). The 150M teacher was skipped (host load), so there is no
  distillation. a10 = anchor 1.0, stopped at step 1250 of 2144 (best checkpoint so far), report-only.
- Temperatures were already fitted in the checkpoint's `heads.json`; export used `--per-channel`; int8 is within the 1-point tolerance
  (largest drop 0.40 points, flags head). Torch vs ONNX fp32 max abs diff 4.8e-6.
- `test` / `testfresh` use the v3 data files for every model. v2 was trained on the v2 data, so v2 vs v3 on `test` is not clean; gold is.
- The matcher calibration is an identity placeholder right now, so default and `PANDA_ROUTER_CALIBRATION=off` agree for v1/v2/v3. The a10
  rows differ because its default run happened while the other worker's matcher edits were landing. The architect re-runs the final comparison.
- True-success n=140 (one run per task): +-4 points is noise. Latency was measured on a loaded host (load 30+); all models share one architecture.

**Recommendation: ship v3.** On gold (359, never trained on) v3 beats v2 on every head: category +4.7 points, difficulty MAE 0.825 vs 0.897,
difficulty rho 0.747 vs 0.705, flags AUROC 0.901 vs 0.886. Routing is equal or better (max-utility regret 0.0021 vs 0.0022, cheapest cost ratio
0.72 vs 0.59, below-min-P 0.224 vs 0.260). True routed success is equal within noise (50.7 vs 50.0 per 100 for cheapest_above_threshold,
45.0 vs 45.7 for max_utility) and attempt-IRT rho is higher (0.212 vs 0.115). Caveats: v3 spends more per 100 tasks on the true-success
eval ($0.149 vs $0.095), and SWE held-out rho is lower (0.081 vs 0.119, CIs overlap). Keep v2 if cost per task matters more than gold accuracy.
Anchor weight 1.0 (a10) hurts gold difficulty (rho 0.549) and is not recommended.
